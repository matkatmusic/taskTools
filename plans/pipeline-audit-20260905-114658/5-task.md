### Step 1 — regeneration test (priority)

`test_generateSteps_theCommittedStepsJsonIsUpToDate`
- Plain-English behavior: regenerating `steps.json` from the live, non-underscore diagrams under `diagrams/tackle-tasks/` and the live block scripts/templates under `scripts/tackle-tasks/` produces byte-identical output to the committed `scripts/steps.json`.
- Steps (as comments in the test body):
  - copy the committed `scripts/steps.json` into a fresh temp file, so `generateSteps()`'s `getMutatingFromPreviousConfig()` read carries forward every hand-written `mutating: true` flag exactly as the committed file has them.
  - run `generateSteps()` against the real `diagrams/tackle-tasks` folder and the real `scripts/tackle-tasks` folder, writing into that temp file, with `allowStubs: false` so a genuinely missing block script/template throws instead of silently stubbing a file into the real source tree.
  - read the temp file back.
  - assert it equals the committed `scripts/steps.json` file's content, byte for byte.
- Failing assertion first (RED): the test does not exist yet, so `node --test tests/generateSteps.test.ts` has one fewer passing test than after this step; adding it and running once with an empty temp file (no seed copy) first shows the diff mismatch (missing `mutating` flags), proving the seed-copy step is load-bearing before locking in the real assertion.
- Minimum code — this is a **test-only** change; no production file needs an edit for this step, since `generateSteps()`, `resolveDiagramFolderSetting()`, and `scripts/steps.json` already exist and are already correct (this test is a drift guard, not a bug fix). `tests/generateSteps.test.ts` already imports everything this test needs at its top (`copyFileSync`, `mkdtempSync`, `tmpdir`, `join`, `readFileSync`, `generateSteps`, all confirmed live at lines 1-11) and already defines `const PROJECT_ROOT = dirname(dirname(fileURLToPath(import.meta.url)));` at line 11 — reuse that constant, add no new imports, add no new `PROJECT_ROOT`-equivalent. Append this test after the last test in the file:

```ts
// npm run steps regenerates it; a stale committed steps.json shows up here, same shape as
// test_generateWorkflow_theCommittedWorkflowIsUpToDate in tests/generateWorkflow.test.ts.
test("test_generateSteps_theCommittedStepsJsonIsUpToDate", () => {
    const committedStepsJsonPath = join(PROJECT_ROOT, "scripts/steps.json");
    const tempConfigPath = join(mkdtempSync(join(tmpdir(), "generate-steps-committed-")), "steps.json");
    // Seeds the previous-config read so hand-written `mutating: true` flags carry forward.
    copyFileSync(committedStepsJsonPath, tempConfigPath);
    generateSteps(join(PROJECT_ROOT, "diagrams/tackle-tasks"), join(PROJECT_ROOT, "scripts/tackle-tasks"), tempConfigPath, false);
    assert.equal(readFileSync(tempConfigPath, "utf8"), readFileSync(committedStepsJsonPath, "utf8"));
});
```

  Note for whichever task lands task 10 (per-task `steps.json`, flagged in the codex review as the reason this test must later target "the generator output against the committed diagrams, not a single committed `steps.json`"): a per-task `steps.json` (e.g. `.taskTools/workflows/<task-number>/steps.json`) is absent the first time it is generated, and `getMutatingFromPreviousConfig()` (`generateSteps.ts:183-197`) reads its `mutating: true` flags from that same output path before overwriting it — generating straight into a fresh per-task path drops every hand-written `mutating` flag. `scripts/steps.json` must stay the one committed, reviewed source of those flags: task 10's per-task generation must seed each new per-task `steps.json` from `scripts/steps.json` before regenerating into it (or move `mutating` declarations to a separate committed source `generateSteps` reads independently of `configPath`). This test's `committedStepsJsonPath` keeps pointing at `scripts/steps.json` regardless of where task 10 routes the generated per-task copies. Out of scope for this task; flagging only so the next diff finds it fast.
