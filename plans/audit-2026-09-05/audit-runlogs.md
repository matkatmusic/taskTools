- **Test? NO.** `rg -l 'no active run for task' --glob '*.test.ts'` returns nothing.
- Open bug.

### 14, 15, 16. Staging-branch-move failures on CREATE_WORKTREE (count 1 + 1 + 1 = 3, same underlying bug, evolving error text)

- Chronology:

  - 2026-09-04T12-15-04 (`refs/heads/staging is merged into HEAD but could not be moved … fatal: cannot force update…`) — this is the **new** throw text `prepareTasks.ts:198` added by that same fix, hit when the regex `used by worktree at '([^']+)'` fails to extract a worktree path from git's stderr.   - 2026-09-04T22-14-02 (task-113) (`Command failed: git -C …/staging merge --ff-only HASH`) — this is the ff-only fallback **itself failing** (line 200's `execFileSync` throwing because the ff-only merge wasn't possible, e.g. the staging worktree had diverged or uncommitted changes).

- **Test? PARTIAL.** `78b1fc1`'s own commit message says `prepareTasks.test.ts` covers "the move and the checked-out error" — i.e. cluster 14/15's scenarios have some coverage — but `rg -l 'could not move refs/heads/staging|is merged into HEAD but could not be moved|merge --ff-only' --glob '*.test.ts'` found no test file using these literal strings, and nothing covers cluster 16 (the ff-only merge itself failing).
